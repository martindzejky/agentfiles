# Fusion motion design

Use the author's detailed craft library as the starting point for design, animation, workflow, and visual review. Preserve its concrete defaults, worked examples, and specialist techniques; a supplied reference, accepted work, or current user instruction takes precedence. Attribution, evidence limits, and the adaptation map are in [sources](references/sources.md).

Execute through the existing native Resolve MCP and [davinci-resolve](../davinci-resolve/SKILL.md). Read [native execution](references/native-execution.md) before scripts: it resolves upstream tool references, current-version lookup, targeting, sandbox access, and partial writes. No additional MCP, animation pipeline, generation provider, scripts, or dependencies are installed by this skill. Construct editable graphics and motion in Fusion; optional HTML stills can support layout planning.

## Working process

1. **Inspect and scope.** Establish the intended project/timeline/item/comp, format, assets, message, and future editing needs. Existing work is the baseline for additions; preserve accepted artwork, keys, curves, controls, and framing outside the change.
2. **Design before building.** Read [architecture](references/architecture.md) and [visual foundation](references/17-visual-foundation.md) for original work. Start with distinct concepts/style frames, choose a direction, then map beats and storyboard. Scale artifacts to the job: a small callout needs less than a film; a local correction does not reopen the whole design.
3. **Build the strongest pose.** Use [construction](references/01-construction.md), then relevant specialist modules. Preserve the design through meaningful native objects, live text, replaceable media, and explicit controls. Verify an extreme pose before propagating a rig.
4. **Animate and review.** Read [animation principles](references/animation-principles.md); choreograph a focal gesture, supporting movement, and readable holds. For whole-frame/reference work use [build orchestration](references/build-orchestration.md). Render, inspect risky in-betweens, watch at speed, and revise against the brief. Numeric audits supplement visual judgment.
5. **Test editability and deliver.** Read [editable rigs](references/06-editable-rigs.md) and [validation/delivery](references/09-validation-delivery.md). Test a real text, media, or control change during animation and restore it. Name the editable result and controls, provide the requested preview/source, and distinguish structural checks, renders, playback, persistence, and user acceptance.

For recorded or recreated interfaces with cursor clicks, see the [worked
button example](references/06-editable-rigs.md#animate-an-interface-button).

## Applying the author's starting point

Keep the craft recommendations specific: use the timing tables, palette systems, easing examples, construction recipes, and review tests as a coherent starting vocabulary. Do not flatten them into generic advice. When modules differ, match the job: reference fidelity preserves measured motion; original design uses the chosen design system; character/collage cadence follows its visual language. A quiet hold and a purposeful cut remain valid when an energetic example suggests drift or a morph.

Technical examples retain upstream version/build assumptions and evidence labels. They are not proof on this installation. Discover current signatures and inputs, use the current project fps/resolution, and probe unfamiliar mechanics in a scratch comp. Upstream font availability, personal provider/music choices, benchmark speedups, and connector guarantees are not facts about the user's setup.
